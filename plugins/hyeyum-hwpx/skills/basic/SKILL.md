# 국어 시험지 HWPX 서식

한글(HWPX) 시험지는 문제 번호·미주·상자·내어쓰기가 서로 얽혀 있어서 한 군데만 어긋나도 한컴에서 모양이 크게 달라진다. 그래서 서식을 눈대중으로 맞추지 않고, 기준 시험지에서 뽑은 값을 스크립트가 그대로 넣게 한다. 사용자(보통 교사)는 글(지문·문항·정답·해설)만 주면 된다. "기준 시험지"는 이 규칙을 뽑은 한컴 저장본으로, 스킬에는 들어 있지 않다.

## 전제
- **코드 실행과 파일 생성이 켜져 있어야 한다.** 이 스킬의 핵심은 파이썬 스크립트(표준 라이브러리만 사용, 네트워크 불필요)로 `.hwpx`를 만드는 것이다. 꺼져 있으면 만들 수 없다고 알리고, 시험 내용을 일반 글(문항별로 읽기 쉽게 정리한 초안)로 주면서 설정에서 코드 실행·파일 생성을 켜면 파일로 만들 수 있다고 안내한다. HWPX XML을 손으로 쓰는 우회는 하지 않는다.
- 만든 파일을 열려면 사용자 컴퓨터에 한컴오피스(한글)가 필요하다.

## 지원하지 않는 것 (요청을 받으면 먼저 알린다 — JSON을 다 쓴 뒤에 알리지 않는다)
부품 목록에 없는 구조는 지원하지 않는다. 아래는 자주 받는 요청이다.
- 서술형·단답형·복수 정답, 선택지가 5개가 아닌 문항, 발문이 `?`로 끝나지 않는 형태(`…을 고르시오.`). 발문을 몰래 `…것은?`으로 고쳐 쓰지 말고 사용자에게 알린다.
- 머리말·쪽번호·이름란, 그림·도표·수식, 칸이 있는 보기 표, 지문 중간의 인용 상자·글감별 어휘 풀이 상자, 선택지 밖의 글자 간격 조정(선택지의 한 글자 넘침을 막는 자간 줄이기만 자동).
- 영어·수학 등 국어 외 과목의 시험지, 학교마다 따로 정한 고유 양식.

## 형식
이 명령의 형식은 아래 하나로 정해져 있다. 형식을 묻지 않는다. JSON의 `format`은 빼도 된다(빼면 이 형식으로 만든다).

### 기본 시험지 (`basic`)
- 이럴 때: 형식을 따로 말하지 않은 일반 시험지. 문항별 배점과 해설(출제 포인트·정답 해설·오답 분석)이 들어가는 정식 시험지.
- 글자: 본문 10pt
- 제목: 가운데 세 줄 15pt
- 발문: `[3.6점]` 배점(필수), 줄간격 125%
- 지문: 문단 테두리로 이어지는 지문, 첫머리 한 칸 들여쓰기
- 보기: 1×1 표(`〈 보 기 〉`)
- 미주: 정답·배점, 출제 포인트, 정답 해설, 오답 분석
- 안내문과 지문 사이: 3pt 빈 줄(자동)

맨 끝에는 새 쪽 맨 위에 `정답과 해설`(13pt 굵게) 제목이 자동으로 붙고 정답·해설(미주)이 그 아래에 모인다. 안내문은 번호 범위 대신 `※`로 시작하고(자동), 표는 모두 글자처럼 취급하는 표이며, 선택지 번호 뒤는 탭으로 맞춰 둘째 줄과 시작 위치가 같다. 문항(발문~⑤)은 단·쪽 경계에서 끊기지 않게 묶이고 첫 묶음 말고는 지문 묶음이 새 단 맨 위에서 시작한다(JSON `group_start`).

제목(학교·학년·과목·차수)은 사용자에게 받는다. 없으면 `중2 국어`·`고1 국어`처럼 학년과 과목만 쓴다. 중학교와 고등학교 시험지는 같은 형식으로 만든다.

## 새 시험지를 만드는 순서
1. 부품을 확인한다: 먼저 `python3 ${CLAUDE_SKILL_DIR}/scripts/components.py`를 실행해 쓸 수 있는 부품, 문항 형식, JSON 항목을 본다(`references/components.md`와 같은 내용). 시험지의 모든 서식은 이 목록의 부품에서만 나오고, 목록에 없는 모양은 만들 수 없다. 요청한 구조가 목록에 없으면 JSON을 쓰기 전에 지원하지 않는다고 알리고, XML을 직접 쓰거나 다른 도구로 흉내 내지 않는다.
2. 내용을 모은다: 지문, 문항(발문·선택지 5개·정답), `basic`은 문항별 배점과 해설(출제 포인트, 정답 해설, 정답을 뺀 선택지 4개의 오답 분석). **실제 작품·교재의 본문은 사용자가 준 것만 쓰고 기억으로 되살려 쓰지 않는다**(인용 오류·저작권 문제). 지문을 직접 쓸 때 출처줄에는 실제 출처를 지어 쓰지 말고 `출제자 창작`이라 적고 사용자에게 알린다. 지문을 줄이거나 발췌하면 문항이 지문 없이 풀리지 않을 수 있으니 줄였다고 알리고, 문항이 묻는 근거가 남아 있는지 확인한다.
3. 내용을 JSON으로 적는다. 형식은 `references/exam-json.md`, 예시는 `assets/examples/`의 JSON(실제 지문·해설로 바꿔 쓴다). 서식은 JSON에 적지 않는다. 글 안의 큰따옴표(`"`)는 `\"`로 쓴다.
4. 시험지를 만든다. 스크립트는 `${CLAUDE_SKILL_DIR}/scripts/`에 있다(Claude Code·Cowork는 이 자리를 스킬 폴더 경로로 바꿔 준다. 일반 채팅처럼 `${CLAUDE_SKILL_DIR}`가 글자 그대로 보이면 스킬 폴더가 코드 실행 환경에 복사된 것이니 이 SKILL.md가 있는 폴더 기준 `scripts/…`로 실행한다):
   ```
   python3 ${CLAUDE_SKILL_DIR}/scripts/build_exam.py 작업폴더/내용.json 작업폴더/시험지.hwpx
   ```
   `build_exam.py` 뒤에 `--parts`를 붙이면 요약 다음 줄에 `쓴 부품: …`이 나와 어떤 부품으로 만들어졌는지 볼 수 있다. 오류는 한국어로 어느 항목이 왜 틀렸는지 알려 준다. **JSON 오류와 검사 실패는 모델이 고치고, 교사에게는 글 내용에 관한 질문만 한다.** 첫 줄의 요약(형식·지문·소제목·출처줄·문항·보기·배점 합·단/쪽 나눔)과 이어지는 `경고`·`쪽별 추정 높이`·`자간 줄임`을 사용자 요청과 맞춰 본다.
5. 규칙을 검사한다. `FAIL`이 없어야 한다(`WARN`은 의도한 지침 이탈이라는 뜻이니 사유를 확인: G6 단·쪽 나눔을 직접 썼을 때, G41 `group_start: flow`일 때):
   ```
   python3 ${CLAUDE_SKILL_DIR}/scripts/verify_exam.py 작업폴더/시험지.hwpx
   ```
   `V9`의 측정값이 미주 형식(정답·포인트·해설·오답분석)과 맞는지도 본다. 실패하면 생성된 XML을 손대지 말고 JSON을 고쳐 4번부터 다시 한다. **같은 `FAIL`이 두 번 이상 반복되면 파일을 전달하지 말고 어떤 규칙이 왜 안 풀리는지 사실대로 알린다.** (한컴이 저장한 사용자 원본 시험지를 검사할 때만 `--lenient`를 붙인다. 원본에는 오타 같은 작은 예외가 있다.)
6. 쪽·단 흐름을 맞춘다(아래).
7. 파일을 환경이 안내하는 출력(다운로드) 폴더에 저장해 사용자가 받게 하고, 없으면 작업 폴더에 두고 이름과 위치를 알린다. 이름 예: `중2_국어_1회.hwpx`.
8. 마지막 응답에 알릴 것: ① 문항 수·형식·배점 합·정답 분포 요약 ② 정답·해설은 초안이라 교사 검수가 필요하다 ③ **정답·해설(미주)이 같은 파일의 맨 뒤에 들어 있으니 학생에게 나눠 주기 전에 분리하거나 그 쪽을 빼야 한다** ④ 지문(작품·교재)의 저작권과 출처 표기는 사용자 책임이다 ⑤ 글꼴(함초롬바탕 등)이 없는 컴퓨터에서는 모양이 달라질 수 있다.

## 쪽·단 흐름
기준 시험지는 단·쪽 나눔 기능을 쓰지 않고 **빈 문단**으로 다음 단까지 밀어낸다(`blank`의 `n`). 그런데 `n`은 글 길이마다 달라서, 렌더로 확인할 수단이 없으면 정확히 맞출 수 없다. 이 환경에는 보통 렌더 도구가 없으므로:
- 새 글감이나 문항 묶음을 **다음 단 머리에서 시작해야 하면 `column_break`**(쪽이면 `page_break`) 항목을 쓴다. 기준 시험지 방식과 달라서 검사기가 `WARN`을 내는 것은 정상이며, 사용자에게 "단 나누기를 썼다"고 알린다.
- **단 나누기는 앞 구간이 한 단에 들어갈 때만 그 자리에 온다.** 앞 구간이 한 단을 넘치면 다음 쪽 왼쪽 단으로 간다. `build_exam.py`가 쪽·단 구간마다 높이를 어림해 `쪽별 추정 높이(pt …; 한 단 658)`로 보여 주고, 한 단을 넘거나 여유가 거의 없으면 `경고`를 낸다(어림 ±10%). 경고가 나면 지문·선택지를 줄이거나 나눔을 더해 구간을 나눈다. 숫자가 한 단의 90% 안팎이면 한컴에서 달라질 수 있으니 여유를 둔다.
- **정답·해설(미주)은 `정답과 해설` 제목이 열어 주는 새 쪽에서 시작한다**: 제목 문단이 스스로 새 쪽을 열므로 맨 끝에 `page_break`나 `end_heading` 항목을 둘 필요가 없다(있어도 같은 결과).
- 기준 시험지 방식(`blank`)을 원하면 어림값으로 넣고 사용자가 한글에서 어긋난 곳을 알려 주면 `n`만 고쳐 다시 만든다. 어림: 본문 높이는 한 단 약 657pt, 빈 문단 하나 약 16pt, `basic` 발문·선택지 한 줄 12.5pt(약 52줄)·지문 한 줄 16pt.
- 렌더 도구(kordoc `render_document` 등)를 쓸 수 있으면 보고 맞추되, 이 렌더는 근사다: 대체 글꼴을 쓰고, 문단 테두리 지문의 상자를 그리지 않으며, 미주 구분선을 쪽 전체 폭으로 그리고, 줄바꿈이 한컴과 다를 수 있다.

## 글을 적을 때 지킬 것
- 문제 번호(`1.`)·선택지 기호(`①`)·배점·정답 번호는 스크립트가 넣는다. 글에는 쓰지 않는다. 선택지는 본문만 적는다(끝 마침표는 아래 '선택지 끝' 규칙). 한 줄은 공백 포함 글자 수로, `basic` 23자 안팎이다. 마지막 줄에 한 글자(+마침표)만 남을 선택지는 스크립트가 그 선택지의 자간을 −1~−7%로 줄여 한 줄 덜 쓰게 한다(`자간 줄임: 문항 2-③ -3%`로 알려 준다. −7%로도 안 되면 경고하니 문구를 줄인다). 선택지 밖의 글자 간격은 건드리지 않는다.
- 낱말·문장 사이는 공백 1칸. 표시 기호 `㉠ ⓐ ㉮`는 앞은 띄우고 뒤는 붙인다(`이동을 ㉠열염 순환이라`). `윗글`은 붙여 쓴다. 한 문단 안에서 줄을 바꾸지 않는다(문단을 나눈다).
- 부정 발문의 `않은·않는·아닌·없는`은 나오는 곳마다 자동으로 굵게+밑줄이 된다. 발문은 `?`로 끝낸다.
- **선택지 끝**: 문장(`~다`·`~군`·`~까`·`~죠`로 끝남)이면 마침표·물음표로 끝내고, 문장이 아니면(명사구·`…함` 뜻풀이·`ⓐ, ⓑ`) 마침표를 찍지 않는다. 끝 글자가 명사와 겹치는 `독자·필요·분야` 같은 것은 글자만으로 판정할 수 없어 쓴 대로 둔다(그 선택지는 사용자 뜻대로 마침표를 직접 확인한다). 말줄임표(`...`)는 그대로 둔다. 원문자 표시 뒤 `:`는 공백 없이 붙인다(`㉠: 설명`).
- **지문의 원문자 표시(㉠ⓐ㉮…)** 바로 뒤에는 가리키는 낱말·문장을 `㉠<u>…</u>`로 밑줄 긋는다(필수, 빠뜨리면 오류). `(가)`·`(나)` 구분 표시는 자동으로 굵게 되고 `(나)`~ 앞에는 빈 줄 1개가 자동으로 들어간다. `줄거리` 표시는 `[…줄거리]`로 묶여 9pt가 된다(같은 문단 `(가) 앞부분 줄거리 | 요약`이든 따로 한 줄이든). 여러 글 묶음의 출처줄은 `paras`에 `- 저자, 「제목」` 문단으로 적는다(자세한 표기는 `references/exam-json.md`).
- 요약 줄의 **`경고:`**에 `…를 고쳤습니다/뺐습니다`가 있으면 빌더가 지침에 맞게 자동으로 고친 것이니 사용자에게 알린다.
- 지문 속에서 문항이 묻는 구절은 `<u>밑줄</u>`로 표시할 수 있다(`**굵게**`와 겹쳐 쓰지 않는다).
- 정답 번호는 고르게 배분한다(5문항 이상이면 한 번호가 40%를 넘으면 경고). 배점이 있으면 배점 합이 시험 만점과 맞는지 사용자에게 확인한다.
- 〈보기〉 안에 칸이 있는 표나 도표가 필요하면 줄글로 풀어 쓴다. 표는 지원하지 않는다(JSON에 `table` 같은 키를 넣으면 오류로 알려 준다).

## 기존 시험지를 이 서식으로 다시 짜 달라고 할 때
사용자가 올린 `.hwpx`는 `python3 ${CLAUDE_SKILL_DIR}/scripts/extract_hwpx_text.py 파일.hwpx`로 글을 순서대로 뽑는다. 표지는 `[발문 N]`, `[선택지]`, `[표 번호(행×열) r,c]`, `[미주 N]`(해당 문항의 선택지 뒤에 나옴)이고, 밑줄은 `<u>…</u>`, 일부만 굵은 글은 `**…**`로 나온다. JSON으로 옮기는 규칙은 `references/exam-json.md` 끝의 표를 따른다.
- **추출이 잃는 것을 사용자에게 알린다**: 끝에 `※`로 시작하는 줄이 나오면(수식·그림·도형·머리말 등) 그 요소는 읽지 못하거나 자리표시로만 나온다. 이 스킬은 그 요소를 만들지 못하니 글로 풀거나 빼겠다고 알린다. 지문 중간의 인용 상자·어휘 풀이 상자도 같다. 옮긴 글이 원문과 같은지(특히 선택지 수, 정답, 부호, 밑줄) 사용자에게 한 번 확인받는다. 표·탭이 낀 글은 일부가 잘릴 수 있으니 원문과 대조한다.
- `.docx`·`.pdf`는 환경에서 쓸 수 있는 읽기 도구로 글을 뽑고, 구형 `.hwp`는 읽지 못하니 한글에서 `.hwpx`나 `.docx`로 다시 저장해 올리게 한다. 해설에 교사 메모(`학교 정답 확인 필요` 등)가 섞여 있으면 그대로 옮기지 말고 사용자에게 묻는다.

## 이미 있는 HWPX를 고칠 때 (MCP 연결 시)
**HWPX 파일을 고치는 도구는 `hyeyum-hwpx-toolkit`(한글(HWPX) 문서 도구함) 하나만 쓴다.** kordoc의 편집 계열 같은 다른 수정 도구는 쓰지 않는다. **읽기·렌더 확인은 kordoc 등 다른 도구를 써도 된다**(kordoc 렌더는 근사). 시험지를 새로 만들거나 서식을 다시 맞출 때는 JSON을 고쳐 `build_exam.py`로 다시 만드는 것이 가장 정확하고, 확신이 없을 때도 그렇게 한다. 상자·미주 같은 새 구조를 넣는 편집은 도구로 하지 말고 JSON으로 다시 만든다(도구로 흉내 내면 부품 모양과 어긋난다).
- 도구 목록에는 `add_paragraphs_ext`·`hwpx_read_layout`·`get_document_info` 같은 핵심 도구만 직접 보인다. 그 밖의 도구(`set_paragraph_format_ext`·`format_text_ext`·`format_table_ext`·`add_endnote_ext`·`insert_inline_ext`·`set_columns_ext`·`set_tab_attributes` 등)는 먼저 `hwpx_tool_schema`(도구 이름)로 인수와 예시를 확인한 뒤 `hwpx_run_edit`(읽기는 `hwpx_run_read`)로 부른다. 도구를 찾으려면 `hwpx_find_tools`를 쓴다.
- 새 문단은 `add_paragraphs_ext`로 문단·글자 모양 id를 직접 지정해 만든다(`add_paragraph`는 직전 문단 모양을 물려받는다). 쓸 id는 `hwpx_read_layout(part="header")`로 찾는다.
- 도구가 다루는 파일은 사용자 컴퓨터의 문서·바탕화면·다운로드 폴더에 있는 것이다. 파일 이름만 쓰면 첫 허용 폴더(확장은 문서 폴더, Claude Code 플러그인은 작업 폴더; 도구 서버 안내문에 목록이 있다)이고, 다른 폴더의 파일은 전체 경로를 쓴다. 사용자에게 폴더를 고르라고 묻지 않는다.
- Claude 일반 채팅에서는 이 스킬의 파일과 스크립트가 Claude의 코드 실행 환경에, MCP 서버는 사용자 컴퓨터에 있어 서로의 파일 경로가 보이지 않는다. 스크립트로 만든 파일을 도구로 고치려면 사용자가 내려받아 허용 폴더에 둔 뒤 알려 줘야 한다. Claude Code에서는 둘 다 같은 컴퓨터에서 돌므로 `build_exam.py`로 만든 파일을 허용 폴더에 저장하면 도구로 바로 고칠 수 있다.

## 더 자세한 규칙
`references/format-spec.md`(목차: 공통 규칙 G1~G50, 형식별 값, 요소별 작성 규칙, 띄어쓰기·글자 간격, 문장 시작 줄 맞춤, 미주, 쪽·단 흐름, 넣지 않은 것). 값이 궁금하거나 `verify_exam.py`의 규칙 ID(G·V)가 무슨 뜻인지 알아야 할 때 해당 절만 읽는다. `assets/templates/`(기준 시험지에서 본문을 비운 뼈대)와 `assets/components/`(부품)는 `build_exam.py`가 알아서 쓴다.
