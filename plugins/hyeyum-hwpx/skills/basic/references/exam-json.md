# 시험 내용 JSON 형식 (`scripts/build_exam.py` 입력)

예시는 `assets/examples/`의 JSON이다. 서식(글꼴·들여쓰기·번호·미주)은 스크립트가 `format-spec.md`대로 넣으므로 JSON에는 **글과 순서만** 적는다. 파일은 UTF-8(BOM 있어도 됨)이어야 한다. 아래 스키마의 `//` 설명은 실제 파일에 넣지 않는다.

```json
{
  "format": "형식 이름",               // SKILL.md "형식"의 이름. 형식이 하나로 정해진 명령에서는 빼도 된다
  "title": ["고1 국어"],               // 제목 줄 목록. `basic`은 1~3줄(학교+학년 / 과목 / 학년도-학기 차수)
  "items": [ ...위에서 아래로 놓일 순서대로... ],
  "group_start": "column"              // (선택) 지문 묶음의 시작: "column"(기본, 새 단 맨 위) · "page"(새 쪽 맨 위) · "flow"(나눔 없음)
}
```

제목 다음의 빈 문단 1개와 맨 끝의 `정답과 해설` 제목은 스크립트가 자동으로 넣는다. `items`는 안내문부터 시작한다. 알 수 없는 키나 알 수 없는 `type`은 조용히 버리지 않고 오류로 알려 준다. 눈에 안 보이는 제어문자(워드·웹에서 복사한 글에 섞인다)는 스크립트가 지우고 경고한다.

## items 항목
| `type` | 필드 | 만드는 것 |
|---|---|---|
| `instruction` | `text` | 안내문. `다음 글을 읽고 물음에 답하시오.`처럼 문장을 적는다 — 앞에 `※ `가 자동으로 붙고, `[1~3]` 같은 문제 번호 범위는 쓰지 않는다(적어도 지운다). 첫 묶음 말고는 안내문이 새 단 맨 위에서 시작한다(`group_start`) |
| `passage` | `paras`, `source`(선택) | 지문. `basic`은 문단 테두리로 이어지는 지문 |
| `question` | 아래 | 발문 + (보기) + 선택지 5개 + 미주 |
| `blank` | `n`(1~200, 기본 1) | 빈 문단 n개(기준 시험지의 쪽·단 맞춤 방식). 안내문 바로 뒤의 `blank`는 글자 3pt 빈 줄이 된다(`basic`은 지문 앞에 3pt 빈 줄이 자동으로 들어가므로 따로 적을 필요 없다) |
| `column_break`, `page_break` | 없음(연달아 두면 오류) | **다음 항목**을 새 단(쪽) 머리에서 시작. 안내문과 지문 사이에는 둘 수 없다(오류) — 안내문과 지문을 함께 새 단(쪽)에서 시작하려면 안내문 앞에 둔다. `items` 맨 끝의 `column_break`는 경고 후 무시된다(정답과 해설 제목이 새 쪽을 연다). 검사기가 `WARN`(G6)으로 알린다. 앞 구간이 한 단에 들어갈 때만 의도한 자리에 오며, 빌드가 구간별 높이를 어림해 넘으면 경고한다. `items` 맨 끝의 `page_break`는 `정답과 해설` 제목이 받으므로 필요 없다(적어도 빈 문단이 따로 생기지 않는다) |
| `end_heading` | `text`(선택) | 마지막 항목으로 `정답과 해설` 제목. **적지 않아도 맨 끝에 `정답과 해설`(13pt 굵게) 제목이 새 쪽 맨 위에 자동으로 붙는다**(있어도 같은 결과). 이 뒤에 미주(정답·해설)가 모인다 |

권장 배치(예시 JSON 참고): 안내문 → 지문 → `blank` 1개 → 문항들(문항 사이 `blank` 1개), 글감 묶음이 바뀌면 `column_break`. 안내문과 지문 사이에는 `blank`를 두지 않는다. `basic`은 안내문 뒤 3pt 빈 줄이 자동으로 들어가고, 발문의 위쪽 간격이 문단 서식에 있어 문항 사이 `blank`가 필수는 아니다.

### passage
- `paras`: 문단 문자열 목록(한 문단 = 한 문자열, 문자열 안에서 줄을 바꾸지 않는다).
  - `**굵게**`: 일부를 굵게. `# 소제목`: 굵은 한 줄 소제목. `""`(빈 문자열): 빈 줄. `<u>밑줄</u>`: 밑줄(`**`와 겹쳐 쓸 수 없다). 짝이 맞지 않는 `**`·`<u>`는 오류다.
  - **원문자 표시 문자(㉠㉡…·ⓐⓑ…·㉮㉯…) 바로 뒤에는 밑줄 범위가 꼭 있어야 한다**: `㉠<u>등대마다 다르다</u>`, `ⓐ“<u>사진만 잃어버린 게 아니었단다.”</u>`. 표시 문자는 밑줄 밖에 둔다(밑줄 안에 적어도 빌더가 밖으로 옮긴다). 낱말은 조사·마침표를 뺀 부분, 문장·대사는 마침표·따옴표까지. 밑줄을 빠뜨리면 오류다.
  - **`(가)`·`(나)` 구분 표시**: 문단 첫머리의 `(가)`는 자동으로 굵게 된다. `(나)`~ 머리 문단 앞에는 빈 줄 1개가 자동으로 들어가고(여러 줄을 적어도 1개), 첫 문단 앞에는 들어가지 않는다.
  - **줄거리 표시**: 두 꼴을 받는다. ① **같은 문단 안**: `(가) 앞부분 줄거리 | 요약…` 또는 `(가) [앞부분 줄거리] 요약…` → `(가)`는 굵게, `[앞부분 줄거리] 요약…` 전체는 9pt(굵지 않게)로 한 문단에 만들어진다(`|` 구분은 대괄호로 고친다). ② **따로 한 줄**: `…줄거리`만 있는 문단(`앞부분의 줄거리`, `(중략 부분 줄거리)`)은 `[…줄거리]` 9pt, 바로 뒤 문단(요약)도 9pt, 요약 뒤에 빈 줄이 들어간다. 낱말은 그대로 둔다(`앞부분 줄거리`·`앞부분의 줄거리`·`중략 부분 줄거리` 모두 가능).
  - `- `로 시작하는 문단은 오른쪽 정렬 출처줄이 된다(`(가)`·`(나)` 묶음마다 출처줄이 있을 때: `"- 이시영, 「그리움」"`).
  - 소제목은 문단 앞 어디에나, 개수 제한 없이 둘 수 있다.
- `basic`은 본문 문단 첫머리에 공백 1칸을 스크립트가 붙인다(들여쓰기). 직접 붙이지 않는다.
- `source`: 지문 맨 끝 출처줄. 직접 지문을 쓴 경우 `출제자 창작`. `basic`은 `- `를 안 써도 스크립트가 붙인다.
- 지문·보기 상자 하나가 한 단(본문 높이 658pt)에 거의 차거나 넘게 추정되면 경고한다. 긴 지문은 `passage`를 둘로 나눈다.
- 모든 표(지문 상자·〈보기〉 상자)는 글자처럼 취급하는 표로 만들어진다.

### question
```json
{"type": "question",
 "stem": "윗글에 대해 이해한 내용으로 적절하지 않은 것은?",
 "answer": 3,                              // 1~5 (숫자)
 "choices": ["…", "…", "…", "…", "…"],     // 정확히 5개. ①~⑤와 번호 뒤 칸은 스크립트가 붙인다 → 본문만(문장이면 마침표로 끝내고, 명사구·나열이면 마침표 없이)
 "score": 3.6,                             // 배점, 소수 첫째 자리까지(아래 설명)
 "bogi": {"lines": ["…", "…"]},            // 선택(아래 설명)
 "note": {"point": "…", "why": "…", "wrong": ["…", "…", "…", "…"]}   // 해설(아래 설명)
}
```
- `stem`: `?`로 끝나는 한 줄. 문제 번호(`1.`)·`[3.6점]`·`**`를 쓰지 않는다. `않은·않는·아닌·없는`은 나오는 곳마다 자동으로 굵게+밑줄이 된다.
- `choices`: 줄바꿈·`**`·선택지 번호(`①`, `1.`)·탭을 쓰지 않는다(번호와 번호 뒤 탭은 스크립트가 넣는다). **문장(서술어로 끝남)이면 마침표(`.`)·물음표(`?`)로 끝내고, 문장이 아니면(명사구·뜻풀이·`ⓐ, ⓑ` 나열) 마침표를 찍지 않는다** — 빌더가 비문장 끝의 마침표를 빼고 알리며, 문장인데 마침표가 없으면 경고한다. 원문자 표시 뒤 `:`는 공백 없이 붙인다(`㉠: …`, 빌더가 고친다). 마지막 줄에 한 글자만 남을 것으로 예측되면 그 선택지의 자간이 자동으로 −1~−7% 줄어든다(요약에 `자간 줄임`으로 표시).
- `score`(`basic`): 필수.
- `bogi`(`basic`): 〈보기〉 상자. `{"lines": […], "source": "출제자 창작, 「제목」", "style": "poem"}`. `lines`는 상자 안 문단 목록(`**굵게**`, `""` 빈 줄, `<u>` 사용 가능). `〈 보 기 〉`가 첫 줄에 자동으로 들어간다(상자는 글자처럼 취급하는 표라 뒤에 빈 문단이 따로 들어가지 않는다). `source`는 오른쪽 출처줄(글머리표가 `- `를 붙인다). `style`은 `"poem"`(시, 기본: 첫 줄 들여쓰기 문단) 또는 `"prose"`(산문: 들여쓰기 없는 문단+첫머리 공백 1칸). 칸이 있는 표는 지원하지 않는다.
- `note`(`basic`, 필수): `point`는 출제 포인트, `why`는 정답 해설, `wrong`은 **정답을 뺀** 선택지 4개의 해설을 번호순으로. 각 항목은 선택지 번호 없이 `‘지문 근거’ — 판단.` 꼴로 적는다(번호는 스크립트가 붙인다).

## 만든 뒤
1. `python3 ${CLAUDE_SKILL_DIR}/scripts/build_exam.py 내용.json 시험지.hwpx` — 첫 줄의 요약(형식·지문·소제목·출처줄·문항·보기·배점 합·빈 문단·단 나눔 수·쪽 나눔 수; 빈 문단 수에는 제목 다음의 자동 빈 문단 1개는 들어가고, 안내문 뒤 3pt 빈 줄과 `정답과 해설` 제목은 들어가지 않는다)과 이어지는 `경고`, 나눔을 썼다면 `쪽별 추정 높이`를 사용자 요청과 맞춰 본다.
2. `python3 ${CLAUDE_SKILL_DIR}/scripts/verify_exam.py 시험지.hwpx` — `FAIL`이 없어야 한다. `V9`(미주 형식)가 만든 형식과 맞는지도 본다.
3. 쪽·단 흐름은 `SKILL.md`의 "쪽·단 흐름"을 따른다.

## 기존 시험지 추출 결과(`extract_hwpx_text.py`)를 JSON으로 옮기는 법
| 추출 줄 | JSON |
|---|---|
| `[발문 N] 윗글에 … 것은? [3.6점]` | `stem`(끝의 ` [3.6점]`은 지운다), `score: 3.6` |
| `[선택지] ① …` 다섯 줄 | `choices`(앞의 `① `는 지운다) |
| `[미주 N] 정답 ⑤   [3.6점]` | `answer: 5`(원문자 → 숫자), `score` 확인 |
| `[미주 N] 출제 포인트  …`, `정답 해설  …` | `note.point`, `note.why`(라벨과 뒤 공백은 지운다) |
| `[미주 N] 오답 분석` 아래 `① …` 네 줄 | `note.wrong`(앞의 번호는 지운다) |
| `[미주 N] ④`만 있는 미주(정답 번호만) | `answer: 4` |
| 〈보기〉 표 칸의 줄들(`[표 n(1×1) 0,0]`) | `bogi.lines`(첫 줄 `〈 보 기 〉`/`<보기>` 라벨은 뺀다. 오른쪽 정렬 출처줄은 `bogi.source`) |
| `**…**`, `<u>…</u>` | 같은 표기를 그대로 쓴다(`<u>`는 지문과 〈보기〉) |
| 본문 맨 끝의 `정답과 해설` 줄 | JSON에 옮기지 않는다(스크립트가 13pt 굵게로 자동으로 넣는다) |
| `[수식: …]`, `[그림]` | 지원하지 않는다 — 사용자에게 알리고 글로 풀거나 뺀다 |

지문 문단은 `passage.paras`로 옮긴다. 소제목은 `# `, 지문 속 인용 상자·어휘 풀이 상자는 지원하지 않으니 줄글로 풀거나 뺀다. 해설에 교사 메모(`학교 정답 확인 필요` 등)가 섞여 있으면 사용자에게 묻는다.
