# 편집 도구 준비 진단(doctor)

편집 도구는 선생님 컴퓨터에서 `uv`라는 실행 도구로 켜지는 프로그램이다. 그래서 준비 여부는 **선생님 컴퓨터**에서 정해진다. 에이전트가 자기 작업 환경(클라우드 컨테이너 등)에 무엇을 설치해도 선생님 컴퓨터는 바뀌지 않으니, 어디에서 일하고 있는지부터 가린다.

**기본은 진단이다.** 이미 준비됐으면 아무것도 설치하지 않고 끝낸다. 설치는 진단에서 빠진 것이 확인됐을 때만 한다. 설치·안내 절차는 상황별 파일에 있으니, 아래 진단 결과가 가리키는 파일 **하나만** 읽고 그 순서대로 한다.

## 1. 도구가 이미 되는지
도구 목록에 서버 `hyeyum-hwpx-toolkit`의 `list_available_documents`가 있으면 불러 본다.
- 문서 목록(빈 목록 포함)이 오면 **준비 완료**다. 설치하지 않고, 다른 파일도 읽지 않는다. "이제 한글 문서를 다룰 수 있어요"라고 알리고 바로 해 볼 요청 하나를 권한다(예: "바탕화면의 ○○.hwpx 글 읽어 줘").
- 준비는 됐는데 선생님이 말한 것이 특정 파일의 문제(안 열림, 깨짐, 내용 이상)라면 도구 문제가 아니다. 여기서 끝내고 hwpx 스킬로 그 파일을 다룬다.
- 도구는 있는데 오류가 나면 `references/troubleshooting.md`를 읽는다.
- 도구가 목록에 없으면 2로 간다.

## 2. 어디에서 일하고 있는지
명령을 실행할 수 있으면 운영체제를 확인한다(`uname -s`, 실패하면 PowerShell `$PSVersionTable.OS` 또는 `ver`). 결과에 따라 읽을 파일이 정해진다.

| 결과 | 뜻 | 읽을 파일 |
|---|---|---|
| Windows 또는 macOS(`Darwin`) | 선생님 컴퓨터에서 직접 명령을 실행한다(Claude 데스크톱 앱의 Code 탭, Claude Code, Codex) | `references/install-direct.md` |
| Linux | 선생님 컴퓨터가 아니다(Claude 채팅의 코드 실행 환경, Cowork의 가상 머신, 클라우드 작업). 여기에 설치해도 도구는 켜지지 않는다 | `references/guide-teacher.md` |
| 명령을 실행할 수 없음 | 선생님이 직접 설치해야 한다 | `references/guide-teacher.md` |

Linux이면 `uv`를 찾거나 설치하지 않고 바로 `references/guide-teacher.md`로 간다. 선생님이 Windows의 WSL(리눅스) 안에서 Codex를 쓴다고 직접 말한 경우에만 Linux를 선생님 컴퓨터로 보고 `references/install-direct.md`를 읽는다(설치 명령은 macOS 줄을 쓴다).

설치나 안내 중에 막히면 그때 `references/troubleshooting.md`를 읽는다.

## 하지 않는 것
- 선생님 컴퓨터가 아닌 곳(2의 Linux)에 `uv`나 파이썬을 설치하고 준비됐다고 말하지 않는다.
- `pip`, 파이썬 따로 설치, `sudo`, PATH·레지스트리 직접 수정, 플러그인 파일 수정으로 우회하지 않는다. 도구는 `uv`가 정해진 부품 목록대로 켜야 한다.
- 진단에서 준비가 됐으면 아무것도 설치하지 않는다.
- 이 스킬로 문서를 고치거나 복구하지 않는다(그건 hwpx 스킬의 일이다).
- `list_available_documents`를 실제로 불러 결과를 보기 전에는 "준비됐다"고 말하지 않는다.
