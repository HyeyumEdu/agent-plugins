# 정답 검증 지침

시험지·문항의 표시된 정답이 맞는지, 복수 정답·정답 없음이 없는지, 해설이 정답과 맞는지 확인한다. 강도에 따라 `guide.py 가림`(정답을 가리고 풀기)과 `guide.py 나눠풀기`(풀이자 서브 에이전트)를 함께 읽는다. 문법 문항이 있으면 `guide.py 문법 검수 --only`의 판정 기준을 쓴다.

## 검증 원칙
<!-- 단계: 전체 -->
- **근거는 지문·〈보기〉 안에서만 찾는다.** 배경지식·교사의 해석·출제 의도로 정오를 가리지 않는다. 근거가 지문 밖(그림, 다른 쪽, 배경지식)에 있으면 그 자체가 문항 문제다.
- **표시된 정답을 정당화하려 하지 말고, 반박하려 한다.** 정답을 먼저 보면 그 답에 맞춰 읽게 되어 복수 정답·정답 없음을 놓친다. 그래서 강도가 '보통' 이상이면 정답을 가리고 먼저 푼다.
- 판정은 문항마다 **근거 구절을 인용**해서 한다. 인용할 수 없는 판정은 '판정 보류'로 둔다.
- 파일은 고치지 않는다. 고쳐 달라고 하면 최소 수정안대로 출제 지침을 지켜 고치고(한글 파일은 hwpx 스킬이나 exam-basic으로 다시 만들기), 고친 문항만 다시 검증한다.

## 검증 강도와 진행
<!-- 단계: 전체 -->
| 강도 | 하는 일 | 읽을 지침 |
|---|---|---|
| 빠르게 | 정답을 보며 선지마다 근거를 확인하고 해설 일치를 본다 | `guide.py 검증` |
| 보통 | 정답을 가린 묶음을 직접 풀고 정답표와 맞춘 뒤, 의심 문항만 반대 해석 | `guide.py 검증,가림,풀이자` |
| 꼼꼼하게 | 정답을 가린 세트 묶음을 풀이자 서브 에이전트들이 나눠 풀고, 대조 뒤 의심 문항은 2차 풀이자 | `guide.py 검증,가림,나눠풀기` (풀이자에게는 `guide.py 풀이자`) |

- 서브 에이전트(하위 에이전트) 도구가 없으면 '꼼꼼하게'는 '보통'으로 하고, 의심 문항은 모두 반대 해석을 거친다. 보고에 그렇게 했다고 알린다.
- **같은 대화에서 직접 만든 문항**은 정답을 가려도 답을 기억하므로 '보통'의 효과가 없다. 서브 에이전트가 있으면 '꼼꼼하게'로 하고, 없으면 '빠르게'에 반대 해석을 더해 하고 "새 대화에서 검증만 부르면 더 정확하다"고 알린다.
- 정답표가 없는 시험지(학교 시험지 복원 등)는 강도와 관계없이 풀어서 정답을 확정한다(`guide.py 분석`의 정답 확정 절차를 함께 따른다).

## 입력 준비
<!-- 단계: 전체 -->
- 한글 시험지(.hwpx)나 시험 내용 JSON(exam-basic 형식): `python3 ${CLAUDE_SKILL_DIR}/scripts/blind.py make 입력 작업폴더`. 교사가 정답표를 따로 줬으면 `--answers 3,5,1,…`(문항 순서대로)를 붙인다. 작업폴더는 시험지와 같은 폴더 안의 `정답검증` 폴더로 한다.
  - '빠르게'도 문항을 같은 형식으로 보려면 make를 쓴다(정답은 `정답표.json`에서 본다).
  - 발문에 자동 번호가 없는 한글 파일이면 make가 문항을 못 찾는다. 그때는 문항을 시험 내용 JSON으로 옮긴 뒤 다시 돌린다.
- PDF·사진·채팅 글: 판독해서(`guide.py 분석`의 판독 규칙) 시험 내용 JSON으로 옮긴다. 정답을 가리려면 **문항만 먼저 옮기고**(정답·해설 칸을 비움) make를 돌린 뒤, 정답은 `--answers`로 넣는다.
- 선택지가 5개가 아닌 문항, 수식·그림이 근거인 문항은 make가 알리거나 자리표시만 나온다. 판정 보류로 두고 알린다.

## 문항 판정 절차
<!-- 단계: 전체 -->
1. **발문**: 긍정·부정, 범위(㉠~㉤, [A]), 단서 조항, 'A는 B와 달리'·'모두'·'각각'·'만' 같은 조건을 적는다.
2. **선지 5개**: 선지마다 참/거짓/애매, 근거 구절 인용, 거짓이면 틀린 말(어느 낱말이 무엇과 어긋나는지)을 적는다.
3. **답 도출**: 부정 발문이면 거짓이 정확히 하나, 긍정 발문이면 참이 정확히 하나여야 한다. 둘 이상이면 복수 정답 소지, 없으면 정답 없음 소지.
4. **대조**: 표시 정답과 비교한다(`blind.py compare`).
5. **반대 해석**(의심 문항): 정답 선지는 일부러 반박하고, 오답 선지는 일부러 변호해 본다. `guide.py 공통 검수 --only`의 '복수 정답·정답 없음 위험 패턴'(P1~P12)을 하나씩 대입한다. 변호가 그럴듯하게 서면 그 선지가 문제다.
6. **해설 일치**: 정답 해설의 근거가 정말 그 정답을 뒷받침하는지, 오답 분석이 정답을 뺀 네 번호를 맞게 다루는지, 해설이 부정 발문인데 '적절한 것'처럼 쓰지 않았는지 본다.

**유형별**
- 조합형(있는 대로·개수형): ㄱ~ㅁ을 하나씩 참/거짓으로 판정한 뒤 선지 조합에 대응시킨다. 진술 하나가 해석에 따라 갈리면 정답 조합이 둘이 된다(P10).
- 'A는 B와 달리'·'모두': A와 B 작품(대목)을 처음부터 끝까지 다시 훑어 해당 요소가 정말 한쪽에만(양쪽에) 있는지 확인한다(P9).
- 문법: `guide.py 문법 검수 --only`의 판정 기준으로만 판정하고 음운 개수·변동 횟수는 계산 과정을 적는다. 학설이 갈리는 분석이면 판정 보류(P4).
- 독서 수치·도표: 계산을 다시 한다. 단위·조건 하나를 놓치지 않았는지 본다.
- 고어·한문: 현대어 풀이가 주어졌는지, 풀이가 갈리는 어휘인지 본다(P11).
- 서술형: 예시 답안이 〈조건〉을 모두 지키는지, 채점 기준의 배점 합이 문항 배점과 같은지, 근거가 지문 안에 있는지 본다.

## 판정 종류
<!-- 단계: 전체 -->
| 판정 | 뜻 |
|---|---|
| 확인 | 풀이 결과가 표시 정답과 같고 근거가 분명하다 |
| 정답 불일치 | 표시 정답이 틀렸을 가능성이 높다(다른 선지가 정답) |
| 복수 정답 소지 | 두 선지 이상이 답이 될 수 있다 |
| 정답 없음 소지 | 발문 조건을 만족하는 선지가 없다 |
| 해설 오류 | 정답은 맞지만 해설 근거·오답 분석 번호·정답표가 틀리다 |
| 판정 보류 | 근거가 지문 밖, 판독 불확실, 학설 차이, 수식·그림 근거 |

`blind.py compare`의 표시는 다시 볼 문항을 고르는 1차 분류다. 최종 판정은 근거를 보고 위 표에서 고른다.

## 보고
<!-- 단계: 전체 -->
1. 한 줄 요약: 문항 수, 강도(풀이자 수), 판정별 개수.
2. **문제 문항부터**: 번호 / 판정 / 근거 인용 / 왜 그런지 / 최소 수정안(바꿀 말 하나. 예: "④의 '반복적으로'를 '한 번'으로"). 복수 정답이면 어느 선지를 어떻게 고치면 정답이 하나가 되는지.
3. 확인된 문항은 표로만(번호 · 정답 · 확인).
4. 판정 보류 문항과 이유, 하지 못한 것(서브 에이전트가 없어 강도를 낮춤, 판독 불확실 등).
5. 이 검증도 초안이라 교사의 최종 확인이 필요하다고 알린다.
