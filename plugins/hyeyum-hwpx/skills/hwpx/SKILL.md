# 한글 문서(HWPX) 고치기

한글 문서는 문단·글자 모양 번호와 표·미주가 서로 얽혀 있어서, 눈대중으로 고치면 한컴에서 모양이 크게 어긋난다. 그래서 편집 도구가 읽어 준 현재 서식을 보고, 도구로만 고친다.

## 전제
- **편집 도구(MCP `hyeyum-hwpx-toolkit`, 한글 문서(HWPX) Toolkit)가 연결돼 있어야 한다.** Claude 일반 채팅은 `.mcpb` 확장을, Cowork·Claude Code는 플러그인을 설치하면 연결된다. 도구가 보이지 않으면 고칠 수 없다고 알리고 설치를 안내한다.
- 파일은 사용자 컴퓨터의 허용 폴더(문서·바탕화면·다운로드, 플러그인은 작업 폴더도)에 있어야 한다. 파일 이름만 쓰면 첫 허용 폴더 기준이고, 다른 폴더는 전체 경로를 쓴다. 사용자에게 폴더를 고르라고 묻지 않는다.
- HWPX를 고치는 도구는 이것 하나만 쓴다. XML을 직접 쓰거나 다른 편집 도구를 쓰지 않는다. 읽기·렌더 확인은 다른 도구를 써도 된다(렌더는 근사라 판단 근거로 쓰지 않는다).

## 부품을 활용할지 정한다
서식 부품은 기준 시험지에서 뽑아 등록해 둔 모양 묶음이다(제목, 안내문, 지문 상자, 발문, 〈보기〉 상자, 선택지, 정답·해설 미주 등. 목록은 exam-basic 스킬의 `references/components.md`). 요청이 분명하면 바로 하고, 애매할 때만 쉬운 말로 한 번 묻는다(예: "고치는 부분을 등록된 서식(부품)에 맞출까요, 아니면 지금 문서 모양대로 고칠까요?").
1. **부품을 활용하지 않기**: 요청한 곳만 도구로 고치고 나머지 서식은 그대로 둔다. 새로 넣는 문단은 문서에 이미 있는 비슷한 문단의 모양 번호를 쓴다.
2. **부품을 활용하기**: 맞는 부품이 있으면 부품 모양을 쓰고, 없으면 에이전트가 모양을 직접 만든다(문서에 이미 있는 비슷한 모양을 바탕으로).
   - exam-basic 스킬로 만든 시험지에는 부품 모양이 이미 들어 있다. `hwpx_read_layout(part="header")`로 모양 번호를 찾아 같은 역할의 문단(예: 발문은 발문 모양)에 적용한다.
   - 부품 모양이 없는 문서에는 지금 도구로 부품을 넣을 수 없다. 시험지 전체를 맞추려면 글을 뽑아 exam-basic 스킬의 "기존 시험지를 이 서식으로 다시 짜 달라고 할 때" 순서로 새로 만들자고 권하고, 아니면 모양을 직접 만들어 고친다.
   - 직접 만든 모양은 그 문서에만 쓰고 부품으로 등록하지 않는다(부품은 개발자가 등록해 배포한 것만 있다). 부품이 아닌 모양을 만들었으면 마지막에 한 줄로 알린다.

## 도구 쓰는 순서
1. 찾고 읽기: `list_available_documents` → `get_document_info`·`get_document_text` → 서식은 `hwpx_read_layout`(문단 번호, 문단·글자 모양 번호, 표·미주).
2. 처음에는 핵심 도구만 보인다. 나머지는 `hwpx_find_tools`(한국어로 찾아도 된다) → `hwpx_tool_schema`(인수와 예시) → `hwpx_run_edit`(읽기는 `hwpx_run_read`)로 부른다.
3. 여러 곳을 바꾸는 수정은 먼저 `dry_run`으로 확인한다. 같은 파일을 이어서 고칠 때는 `expected_revision`으로 그 사이 파일이 바뀌지 않았는지 확인한다.
4. 새 문단은 `add_paragraphs_ext`로 문단·글자 모양 번호를 직접 지정해 만든다(`add_paragraph`는 직전 문단 모양을 물려받는다). 쪽·단 설정을 가진 첫 문단(0번) 앞에는 넣지 않는다.
5. 고친 뒤 읽기 도구로 다시 읽어 바뀐 곳을 확인한다. 일부 도구는 대상을 못 찾아도 성공처럼 응답한다.

## 요청별 도구
`hwpx_find_tools`로 찾을 때 아래 이름을 먼저 본다(인수는 `hwpx_tool_schema`).
- 글 바꾸기: `replace_text_ext`(미주·각주·머리말·표 칸 안까지 찾고 서식은 그대로. 정답·해설 미주를 고칠 때도 이것), 한 문단 글 고치기 `edit_paragraph_text_ext`, 문단 나누기·합치기 `split_paragraph_ext`·`merge_paragraphs_ext`.
- 개체: 미주·각주·수식·그림·링크 하나 지우기 `delete_inline_object_ext`, 수식 내용·그림 크기·링크 주소 바꾸기 `update_inline_object_ext`.
- 표: 행·열 넣기/지우기와 칸 나누기 `edit_table_structure_ext`, 표 나누기·다음 표와 합치기 `split_table_ext`·`merge_table_with_next_ext`.
- 문서: 머리말·꼬리말 지우기 `remove_header_footer_ext`, 보내기 전 작성자·미리보기 정보 지우기 `sanitize_document_ext`.
- 개인정보 가리기 `redact_text_ext`: 가린 뒤에도 백업(`.bak`)에는 원래 정보가 남는다. 다 확인했으면 백업을 지우자고 권한다(아래 "백업 파일 지우기").

## 백업과 되돌리기
- 도구는 고치기 직전 상태를 `파일이름.hwpx.bak` 하나로 남긴다(고칠 때마다 새로 덮어쓴다).
- 고친 뒤에는 "마음에 들지 않으면 수정 전으로 되돌릴 수 있다"고 알린다. 되돌릴 때는 `undo_last_edit`를 쓴다(한 번 더 쓰면 다시 고친 상태가 된다). 여러 번 나눠 고친 경우 되돌리면 마지막 수정 하나만 취소된다.
- 여러 단계로 크게 고칠 때는 시작 전에 `copy_document`로 원본 사본을 따로 만들어 두자고 권한다.

## 백업 파일 지우기
사용자가 백업을 지워 달라고 하면 `delete_backups_ext`를 쓴다. 한 폴더 안(하위 폴더 제외)의 `*.hwpx.bak` 파일만 지운다. 먼저 `dry_run: true`로 지울 파일 목록을 보여 주고, 사용자가 확인하면 지운다. 지운 백업으로는 되돌릴 수 없다는 점을 함께 알린다.
